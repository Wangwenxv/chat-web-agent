# 2026-09-24

## 提示词缓存（prompt caching）改造

问题：用户反馈经过本工程的 AI "没有缓存"（API 侧无 cached tokens），询问与一般 agent 应用的差别。

诊断结论：
- 本工程是纯浏览器前端 + 通用 OpenAI 兼容客户端，请求体没有任何缓存相关字段。
- `buildSystemPrompt` 把"工作区文件快照"（含 rev/字符数，每次编辑都变）嵌在系统提示词尾部 → 前缀缓存在此处截断，其后的全部历史消息每步全量重算。
- usage 类型只含 3 个基础字段，缓存命中数据即使返回也看不到。

改造（已完成，typecheck/lint/build 全过）：
- prompt.ts：系统提示词保持静态；新增 `buildWorkspaceSnapshotMessage`，快照改为尾部独立 user 消息注入（历史消息之后）。
- client.ts：新增 `resolveCacheControl`（auto=模型名含 claude/anthropic 时打 cache_control；on=强制；off=关闭）、`applyCacheBreakpoints`、`applyToolCacheControl`、`cachedTokensOf`/`accumulateTurnUsage`（归一化 DeepSeek/OpenAI/Anthropic 三家缓存字段）；请求加 `stream_options.include_usage`。
- types.ts：新增 `PromptCacheMode`、`ModelUsage`、`TurnUsage`；`ChatMessageRecord.usage`。
- runner.ts：每步传 `cacheBreakpoints: [0, len-2]`（system + 最后一条历史消息），累计整回合 usage 挂到最终消息与 turn_end 事件。
- repository.ts：默认设置 `promptCacheMode: 'auto'`（老数据经 DEFAULT_SETTINGS 合并自动迁移）。
- SettingsModal：新增"提示词缓存"下拉；MessageView：最终回答底部显示 prompt/缓存命中/输出 tokens。

用户环境：第三方中转网关，服务商不确定 → 采用分服务商自适应方案。

环境备注：本会话 Bash 工具环境损坏（核心命令缺失），PowerShell 工具不回显 stdout；验证命令需把输出用 `[System.IO.File]::WriteAllText` 写 UTF-8 文件再用 Read 查看。
